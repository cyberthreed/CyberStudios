### 🔐 report a vulnerability privately

GitHub private vulnerability reporting is enabled for this repository.

1. Open the repository's [Security Advisories page](https://github.com/cyberthreed/CyberStudios/security/advisories).
2. Select **Report a vulnerability** and complete GitHub's private report form. You may need to sign in.
3. Share enough detail for the maintainers to understand and reproduce the issue safely.

Please include the affected project, version or commit, operating system, relevant configuration, reproduction steps, expected impact, and a minimal proof of concept where useful.

Remove unrelated personal information. Do not send real passwords, API keys, session tokens, or private user data; use clearly marked dummy values.

**Keep exploitable details out of public issues, pull requests, and community chats while we assess the report.** If the private-report button is unavailable, open a minimal [issue](https://github.com/cyberthreed/CyberStudios/issues) asking for a private reporting route, without technical details or a proof of concept.

### 🛠️ what to report

Examples include unintended code execution, unauthorized access, credential exposure, unsafe handling of untrusted content, or a privacy issue that exposes data unexpectedly.

Ordinary crashes, broken links, visual problems, and feature requests can use the public issue tracker when they contain no sensitive security information.

### 🫧 versions & project status

This repository contains several projects with different release cycles. Please report the exact affected component and version. Where practical, check the latest public release or current `main` source to help establish whether the issue is still present.

Reports about older versions are welcome, but fixes for older releases, response deadlines, and patch schedules are not guaranteed. Some projects are experimental or in development; consult their individual documentation for current status.

### 🤝 a considerate research process

Use your own local test environment and data, or obtain explicit permission for any other environment you test. Avoid accessing other people's data, disrupting services, collecting credentials, or testing third-party systems as part of a CyberStudios report.

We'll review reports as capacity allows and use the private report thread to discuss reproduction, impact, and possible fixes. Coordinate disclosure there so we can consider a fix or mitigation before technical details are published. This policy does not authorize access to systems or data you do not control.
